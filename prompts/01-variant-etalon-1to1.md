# Промпт 01 — Вариант 1: схема 1:1 по эталону, типы в современном виде

> **Часть проекта.** См. [README](../README.md) и [00-MAIN-PROMPT](../../docs/prompts/00-MAIN-PROMPT.md).
>
> **Эталон:** `Sh_29-06-25` — рабочая БД складского модуля (выгрузка структуры и
> данных: [`../../docs/reference/target-model/`](../reference/target-model/README.md)).

## 1. НАЗНАЧЕНИЕ

Схема, повторяющая эталон **один в один**: те же 22 таблицы, те же бизнес-сущности
(накладные, движения по складам, две единицы измерения, аудит-метки, деньги клиента),
но без технического мусора 2006 года. Цель — чтобы новое приложение (.NET 8, Dapper,
Angular) работало с теми же сущностями и с теми же данными, а данные переносились
одной командой.

**Что меняем:** только техническое. **Что не меняем:** состав таблиц, бизнес-логику,
названия таблиц (включая опечатку «Скдад»).

## 2. ПРАВИЛА ПРЕОБРАЗОВАНИЯ

| Эталон | Новая схема | Зачем |
|--------|-------------|-------|
| `nchar(n)`, `char(n)` | `nvarchar(n)` | `nchar` добивает пробелами справа: `'Ткань '` ≠ `'Ткань'`, ломаются JOIN и сравнения |
| `float` | `decimal(18,3)` | Остатки не «плывут» от округлений, суммы сходятся до копейки |
| `коэфициэнтПриведения...` (float) | `decimal(18,6)` | Коэффициент перевода единиц — дробь с точностью до 1e-6 |
| `smallmoney`, `money` | `decimal(18,2)` | Единый денежный тип |
| `smalldatetime` | `datetime` | Диапазон 1970–2079 в `smalldatetime` уже не нужен |
| PK из строк (`AliasЕдИмТовар.название`, `Матерьял.название`, `АудитМетка.номерГруппы`, `ОсновнаяЕдИзмерения.название`, `АтрибутыМатерьяла.название`) | `Id int IDENTITY(1,1)` PK + `UNIQUE` на исходную строку | Строковые PK раздувают индексы и мешают JOIN |
| FK, ссылающиеся на строковый ключ | Дочерняя колонка становится int: `AliasЕдИм → AliasЕдИмId`, `ОснЕдИм → ОснЕдИмId`, `аудитНомерГруппы → аудитНомерГруппыId`, `матерьял → матерьялId`, `основнаяЕдИзмерения → основнаяЕдИзмеренияId`, `тараРасхода → тараРасходаId`, `значение → значениеId` | Интегральные связи вместо строковых |
| Таблицы без PK (`АУДИД`, `ПРИХОД`, `РАСХОД`) | Добавлен `Id int IDENTITY(1,1)` | Строки нельзя ни найти, ни обновить |
| Составной PK `СвязиAlisEдИмНоменклатура(aliasЕдИм, idНоменклатура)` | `Id` PK + `UNIQUE(aliasЕдИмId, idНоменклатура)` | Тот же составной смысл, но без строки в ключе |
| CHECK-ограничения отсутствуют | Добавлены на количество и суммы | Мусор в данных ловится базой, а не отчётом |

**Ограничения по CHECK — из фактических данных, а не из здравого смысла:**

- `> 0` — только `СкладПриход/СкладРасход.колОснЕдИм`, `ПРИХОД/РАСХОД.кол`
  (в эталоне нулей нет);
- `>= 0` — `АУДИД.количест` (30 нулей), `колAliasЕдИм` (нули во **всех** строках —
  упаковочные количества просто не ведутся), `РезультатАудита.недостача`, все цены и суммы.

**Каскады:** `ON UPDATE/DELETE NO ACTION` — как в эталоне. `ON UPDATE CASCADE` даёт
«multiple cascade paths» на `ПеремещениеПоСкладам` (два FK на `Скдад`).

## 3. ИМЕНА — НЕ ТРОГАЕМ

Названия таблиц и колонок сохраняются как есть, включая опечатки эталона:

| Опечатка эталона | Как есть |
|------------------|----------|
| `Скдад` | переименование сломает `INSERT…SELECT` при миграции |
| `комeнтарий` (одна «м») в `КлиентМеткаРасчет` | переименование потребует правки в коде legacy |
| `cуммаПринятыхДенег` (латинская `c`) | |
| `коэфициэнтПриведенияКоснЕдИзм` | |

**Важно при доработке скриптов:** русские имена содержат латинские и кириллические
омоглифы (`Alis` / `Аlias`, `ЕдИм` / `ЕдИзм`). Имя, набранное руками, может отличаться
от каталога на одну букву и дать `Invalid column name`. Все имена в скриптах
генерируются из `sys.columns`/`sys.tables` — не правьте их вручную, это ломает перенос.

## 4. СОСТАВ СХЕМЫ

**Справочники:** `Скдад`, `Матерьял`, `ОсновнаяЕдИзмерения`, `AliasЕдИмТовар`,
`АтрибутыМатерьяла`, `Поставщик`, `Клиент`, `Номенклатура`,
`СвязиAlisЕдИмНоменклатура`, `ХарактеристикаНоменклатуры`.

**Накладные:** `НакладнаяПриход`, `НакладнаяРасход`.

**Движения:** `СкладПриход` (469), `СкладРасход` (6304), `ПРИХОД` (81), `РАСХОД` (126),
`ПеремещениеПоСкладам` (0).

**Деньги клиента:** `КлиентМеткаРасчет` (198), `КлиентДеньги` (2134).

**Аудит:** `АудитМетка` (5), `РезультатАудита` (758), `АУДИД` (202).

## 5. ФАЙЛЫ

```
db/variant1-etalon/
├── create-database.sql                     — создание БД SkladEtalon
├── create-tables.sql                       — 22 таблицы, порядок зависимостей
├── create-indexes.sql                      — 44 индекса (FK + отчёты + остатки)
├── migrate-data-from-Sh_29-06-25.sql       — перенос всех данных эталона
└── database-schema.md                      — описание, ER-диаграмма, запросы
```

Скрипты идемпотентны: `create-tables.sql` пересоздаёт таблицы (сброс идёт от
зависимых к зависимым), миграция данных вставляет только отсутствующие строки.

## 6. РАЗВЁРТЫВАНИЕ

```bash
sqlcmd -S localhost -E -f 65001 -b -i create-database.sql
sqlcmd -S localhost -E -f 65001 -b -i create-tables.sql
sqlcmd -S localhost -E -f 65001 -b -i create-indexes.sql
sqlcmd -S localhost -E -f 65001 -b -i migrate-data-from-Sh_29-06-25.sql
```

Миграция требует, чтобы обе базы лежали на одном экземпляре (переливка идёт
через `[Sh_29-06-25].dbo.*`). Для другого сервера: выгрузить эталон через SSMS
(Generate Scripts + Data) и заменить префикс на `dbo`.

## 7. ЧТО ОСТАЁТСЯ НА СОВЕСТЬ РАЗРАБОТЧИКА

1. **Логика в БД.** В эталоне 9 процедур и 3 представления: `ВналичиеНаСкладе`,
   `КлиентДолг`, `КлиентМеткаРасчетMax`, `GetProdyktbyPeriod`, `GetПоставкиЗаПериод`,
   `ПриходНаГруппу`, `РасходНаГруппу`, `РезультатыАудита`. Они остаются
   «чёрным ящиком» — переносить или заменять на Dapper-запросы.
2. **Связь склад ↔ деньги.** В эталоне она косвенная: у расхода своя накладная,
   деньги привязаны к метке расчёта. Согласовать документы вручную нельзя —
   если нужна явная связь, это уже вариант 2.
3. **Бизнес-правила в коде.** Тип операции, вид оплаты, порядок расчёта долга —
   нигде не зафиксированы.
4. **`Identity`-колонки.** `Скдад.id` в эталоне не `IDENTITY` — так и оставлено;
   новые склады надо вставлять с явным `id`.

## 8. ОГРАНИЧЕНИЯ

- ❌ НЕ переименовывать таблицы и колонки (ломается миграция и legacy-код).
- ❌ НЕ возвращать `nchar`/`float`/`smallmoney` — ради этого всё затевалось.
- ❌ НЕ ставить `CHECK > 0` на `колAliasЕдИм` и `АУДИД.количест` — данные не пройдут.
- ❌ НЕ добавлять `ON UPDATE CASCADE` на ссылки на `Скдад` — конфликт путей каскадов.
- ✅ Сохранять исходные `Id` при переносе (`IDENTITY_INSERT`).
- ✅ Держать порядок вставки: справочники → деньги/метки → накладные → движения → аудит.
