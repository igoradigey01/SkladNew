# Вариант 3: характеристики по мотивам Microsoft Dynamics 365

> **Часть проекта.** См. [Главный промпт](00-MAIN-PROMPT.md).
> Схема: [`db/sklad_v4/database-schema.md`](../db/sklad_v4/database-schema.md).

## 1. ЗАМЫСЕЛ

Версия 3 (`Sklad-v3`) умела хранить характеристики вида номенклатуры
(«Толщина», «Цвет»), но не умела сказать, **какого они типа** и **какие
значения допустимы**. Версия 4 добавляет оба, а заодно — наследование
значений по виду номенклатуры.

Источник идей — Microsoft Dynamics 365 Supply Chain Management:

| Dynamics 365 | Наша схема |
|--------------|------------|
| Attribute type (тип атрибута) | `ТипЗначения` |
| Attribute (атрибут) | `Характеристика` |
| Набор допустимых значений | `СписокЗначений` |
| Значение атрибута в карточке | `ЗначениеХарактеристики` |
| Category (категория) | `ВидНоменклатуры` |
| Released Product | `Номенклатура` |

Ключевая идея Dynamics: **атрибут заводится на категорию и наследуется всеми
продуктами этой категории**, а значение по умолчанию переопределяется в
карточке конкретного продукта. У нас категория — вид номенклатуры.

## 2. ЧТО ОСТАЁТСЯ БЕЗ ИЗМЕНЕНИЙ

Ядро не трогаем: `Приход` / `Расход` / `Деньги` на общем `UETR`,
`Ревизия` / `Расхождение`, справочники `Клиент`, `Поставщик`, `Склад`,
`ЕдИзмерения`, `ГруппаНоменклатуры`, `КатегорияНоменклатуры`, сама
`Номенклатура` с ценами и складскими параметрами.

## 3. НОВЫЕ СУЩНОСТИ

### `ТипЗначения` — тип атрибута

```sql
CREATE TABLE dbo.ТипЗначения
(
    Id         int IDENTITY(1, 1) NOT NULL,
    Название   nvarchar(50) NOT NULL,     -- Text, Number, Date, Bool, List
    Описание   nvarchar(200) NULL,
    CONSTRAINT PK_ТипЗначения PRIMARY KEY CLUSTERED (Id),
    CONSTRAINT UQ_ТипЗначения_Название UNIQUE (Название)
);
```

Справочник, а не перечисление: новый тип можно завести, не меняя структуру
таблиц.

### `Характеристика` — атрибут вида

```sql
CREATE TABLE dbo.Характеристика
(
    Id                int IDENTITY(1, 1) NOT NULL,
    ВидНоменклатурыId int NOT NULL,
    ТипЗначенияId     int NOT NULL,
    Название          nvarchar(100) NOT NULL,
    Описание          nvarchar(500) NULL,
    Порядок           int NULL,
    Обязательный      bit NOT NULL DEFAULT (0),
    Минимум           decimal(18, 3) NULL,   -- Number
    Максимум          decimal(18, 3) NULL,   -- Number
    МаксимальнаяДлина int NULL,             -- Text
    МинимальнаяДата   date NULL,             -- Date
    МаксимальнаяДата  date NULL,             -- Date
    ЗначениеПоУмолчанию nvarchar(200) NULL, -- наследуется позициями вида
    Активен           bit NOT NULL DEFAULT (1),
    ДатаСоздания      datetime NOT NULL DEFAULT (GETDATE()),
    CONSTRAINT PK_Характеристика PRIMARY KEY CLUSTERED (Id),
    CONSTRAINT FK_Характеристика_ВидНоменклатуры FOREIGN KEY (ВидНоменклатурыId)
        REFERENCES dbo.ВидНоменклатуры (Id) ON UPDATE CASCADE ON DELETE CASCADE,
    CONSTRAINT FK_Характеристика_ТипЗначения FOREIGN KEY (ТипЗначенияId)
        REFERENCES dbo.ТипЗначения (Id) ON UPDATE CASCADE ON DELETE NO ACTION,
    CONSTRAINT UQ_Характеристика_Вид_Название UNIQUE (ВидНоменклатурыId, Название)
);
```

### `СписокЗначений` — допустимые значения типа List

```sql
CREATE TABLE dbo.СписокЗначений
(
    Id               int IDENTITY(1, 1) NOT NULL,
    ХарактеристикаId int NOT NULL,
    Значение         nvarchar(200) NOT NULL,
    Порядок          int NULL,
    CONSTRAINT PK_СписокЗначений PRIMARY KEY CLUSTERED (Id),
    CONSTRAINT FK_СписокЗначений_Характеристика FOREIGN KEY (ХарактеристикаId)
        REFERENCES dbo.Характеристика (Id) ON UPDATE CASCADE ON DELETE CASCADE,
    CONSTRAINT UQ_СписокЗначений_Характеристика_Значение UNIQUE (ХарактеристикаId, Значение)
);
```

### `ЗначениеХарактеристики` — значение у позиции

```sql
CREATE TABLE dbo.ЗначениеХарактеристики
(
    Id               int IDENTITY(1, 1) NOT NULL,
    НоменклатураId   int NOT NULL,
    ХарактеристикаId int NOT NULL,
    Значение         nvarchar(500) NOT NULL,
    ДатаИзменения    datetime NOT NULL DEFAULT (GETDATE()),
    CONSTRAINT PK_ЗначениеХарактеристики PRIMARY KEY CLUSTERED (Id),
    CONSTRAINT FK_ЗначениеХарактеристики_Номенклатура FOREIGN KEY (НоменклатураId)
        REFERENCES dbo.Номенклатура (Id) ON UPDATE NO ACTION ON DELETE CASCADE,
    CONSTRAINT FK_ЗначениеХарактеристики_Характеристика FOREIGN KEY (ХарактеристикаId)
        REFERENCES dbo.Характеристика (Id) ON UPDATE NO ACTION ON DELETE NO ACTION,
    CONSTRAINT UQ_ЗначениеХарактеристики_Ном_Хар UNIQUE (НоменклатураId, ХарактеристикаId)
);
```

## 4. НАСЛЕДОВАНИЕ ЗНАЧЕНИЙ

```
Значение = ЗначениеХарактеристики (позиция)     — если строка есть;
         иначе Характеристика.ЗначениеПоУмолчанию (наследование от вида);
         иначе NULL.
```

Готовое представление `dbo.vw_ЗначенияХарактеристик` отдаёт это вместе с
колонкой `Источник` (`позиция` / `по умолчанию` / `не задано`).

## 5. ПРОВЕРКА ЗНАЧЕНИЙ — ПОЧЕМУ ТРИГГЕРЫ

Правила зависят от типа значения, а тип лежит в другой таблице, список
допустимых значений — в третьей. В `CHECK`-ограничении подзапросы запрещены
(«Subqueries are not allowed in this context»), поэтому типозависимые правила
вынесены в триггеры:

| Триггер | Событие | Что проверяет |
|---------|---------|---------------|
| `TR_Характеристика_Проверка` | INSERT / UPDATE `Характеристика` | `ЗначениеПоУмолчанию` по типу |
| `TR_ЗначениеХарактеристики_Проверка` | INSERT / UPDATE `ЗначениеХарактеристики` | значение позиции по типу |
| `TR_СписокЗначений_Проверка` | DELETE `СписокЗначений` | значение из списка уже используется — удалить нельзя |

Правила по типам:

- `Text` — длина ≤ `МаксимальнаяДлина`;
- `Number` — преобразуется в число, лежит в [`Минимум`, `Максимум`];
- `Date` — преобразуется в дату, лежит в [`МинимальнаяДата`, `МаксимальнаяДата`];
- `Bool` — `0`/`1`/`true`/`false`/`да`/`нет`;
- `List` — значение есть в `СписокЗначений`.

## 6. ПОРЯДОК ЗАПОЛНЕНИЯ

`СписокЗначений` ссылается на `Характеристика`, поэтому для типа `List`:
характеристика → список значений → значение по умолчанию.

Для остальных типов умолчание можно задать сразу — оно проверяется по
диапазону.

## 7. ЧТО НЕ ПЕРЕНОСИМ

**Released Product.** В Dynamics продукт — глобальное определение, а
выпущенный продукт — его выпуск в конкретную компанию со своими ценами и
налогами. У нас одно юридическое лицо, поэтому роль выпущенного продукта
играет сама `Номенклатура`. Если компаний станет несколько — понадобится
отдельная таблица выпусков.

## 9. ПРОВЕРКА

`verify-data.sql` — все проверки возвращают пустой результат, если всё в
порядке:

1. состав базы;
2. контрольные суммы прихода, расхода, сальдо и денег — против `Sklad-v3`
   и эталона;
3. сироты по внешним ключам;
4. нарушения `CHECK`-ограничений;
5. значения, не соответствующие типу; умолчание типа List вне списка;
   дубли значений;
6. битые ссылки на кадровую базу `Sklad_v1_HR`;
7. пустой `UETR`, полные дубли строк движений.
