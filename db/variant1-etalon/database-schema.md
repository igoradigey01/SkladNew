# Схема БД `SkladEtalon` — вариант 1 (1:1 по эталону)

Схема повторяет рабочую БД `Sh_29-06-25` (22 таблицы) один в один, но с типами
в современном виде и без строковых первичных ключей. Идея и правила преобразования —
в [промте варианта 1](../../prompts/01-variant-etalon-1to1.md).

## Файлы

| Файл | Что делает |
|------|------------|
| `create-database.sql` | Создаёт `SkladEtalon` (`Cyrillic_General_CI_AS`, compat 150) |
| `create-tables.sql` | 22 таблицы в порядке зависимостей, с FK и CHECK |
| `create-indexes.sql` | 44 индекса: все FK + выборки под остатки и отчёты |
| `migrate-data-from-Sh_29-06-25.sql` | Переносит все данные эталона (12 108 строк) |

Порядок запуска — сверху вниз, скрипты идемпотентны:

```bash
sqlcmd -S localhost -E -f 65001 -b -i create-database.sql
sqlcmd -S localhost -E -f 65001 -b -i create-tables.sql
sqlcmd -S localhost -E -f 65001 -b -i create-indexes.sql
sqlcmd -S localhost -E -f 65001 -b -i migrate-data-from-Sh_29-06-25.sql
```

## Что изменилось против эталона

| Было | Стало | Зачем |
|------|-------|-------|
| `nchar(n)`, `char(n)` | `nvarchar(n)` | `nchar` добивает пробелами — ломает сравнения и JOIN |
| `float` | `decimal(18,3)` | Остатки без ошибок округления |
| `коэфициэнтПриведенияКоснЕдИзм` (float) | `decimal(18,6)` | Точность перевода единиц |
| `smallmoney`, `money` | `decimal(18,2)` | Единый денежный тип |
| `smalldatetime` | `datetime` | Диапазон `smalldatetime` исчерпан |
| 5 строковых PK | `Id int IDENTITY` + `UNIQUE` на строку | Нормальные ключи и индексы |
| FK на строковые ключи | Дочерние колонки стали `int` (`AliasЕдИмId`, `ОснЕдИмId`, `аудитНомерГруппыId`, `матерьялId`, `основнаяЕдИзмеренияId`, `тараРасходаId`, `значениеId`) | Интегральные связи |
| `АУДИД`, `ПРИХОД`, `РАСХОД` без PK | Добавлен `Id int IDENTITY` | Строки можно найти и обновить |
| CHECK-ограничений нет | Есть на количествах и суммах | Мусор ловит база |

Названия таблиц и колонок сохранены как в эталоне, включая опечатки
(`Скдад`, `комeнтарий`, `cуммаПринятыхДенег`): переименование сломало бы
миграцию данных и legacy-код.

При переносе: строковые ссылки подставляются подзапросом по названию, хвосты
пробелов от `nchar` обрезаются (`RTRIM`), `money`/`smallmoney`/`float`
приводятся к `decimal`, исходные `Id` сохраняются через `IDENTITY_INSERT`.

## Ключевые запросы

**Остаток по номенклатуре и складу** (логика `ВналичиеНаСкладе`):

```sql
SELECT  n.[id],
        n.[название],
        ISNULL(p.Приход, 0) - ISNULL(r.Расход, 0) AS Остаток
FROM    dbo.[Номенклатура] AS n
LEFT JOIN (SELECT [номенклатура], SUM([колОснЕдИм]) AS Приход
           FROM dbo.[СкладПриход] GROUP BY [номенклатура]) AS p ON p.[номенклатура] = n.[id]
LEFT JOIN (SELECT [номенклатура], SUM([колОснЕдИм]) AS Расход
           FROM dbo.[СкладРасход] GROUP BY [номенклатура]) AS r ON r.[номенклатура] = n.[id];
```

**Отгрузка за период по клиенту** (аналог `GetProdyktbyPeriod`):

```sql
SELECT  k.[ФИО],
        r.[дата],
        r.[номер],
        SUM(s.[колОснЕдИм] * s.[ценаОснЕдИм]) AS Сумма
FROM    dbo.[СкладРасход] AS s
JOIN    dbo.[НакладнаяРасход] AS r ON r.[id] = s.[накладнаяId]
JOIN    dbo.[Клиент] AS k ON k.[id] = r.[клиентId]
WHERE   r.[дата] >= @from AND r.[дата] < @to
```
