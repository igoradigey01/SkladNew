# Схема БД `Sklad-v3` — версия 3

Версия 2 (`Sklad-v2`) + расширенный справочник номенклатуры: коды, Guid,
классификация по группам и категориям, три цены, складские параметры и
характеристики, привязанные к виду номенклатуры.

Кадры по-прежнему в отдельной базе [`Sklad_v1_HR`](../sklad_v1_hr/database-schema.md),
связь — через `СотрудникGuid`.

## Что изменилось относительно `Sklad-v2`

| Таблица | Изменения |
|---------|-----------|
| `Номенклатура` | `Guid` (UNIQUE), `Код` (UNIQUE), `Артикул`, `КраткоеНазвание`, `ГруппаId`, `КатегорияId`, `ТипId`, три цены (закупочная/продажная/оптовая), `МинимальныйОстаток`, `МаксимальныйОстаток`, `СрокГодности`, `СтранаПроисхождения`, `Фото`, `Описание`, `Активен`, `ДатаСоздания`, `ДатаИзменения`. Прежние `Цена` и `ЕдИзмеренияId` заменены на `ЦенаПродажная` и `БазоваяЕдИзмId` |
| `ВидНоменклатуры` | добавлено `Описание` |
| `ЕдИзмерения` | `Название` расширено до 50, добавлено `Сокращение` |
| `Характеристика` | теперь принадлежит виду номенклатуры: `ВидНоменклатурыId`, `Порядок`, `Обязательный` |
| `ЗначениеХарактеристики` | `Значение` расширено до 200, добавлен `UNIQUE (НоменклатураId, ХарактеристикаId)` |
| `ГруппаНоменклатуры` | **новая** — дерево групп через `РодительId` |
| `КатегорияНоменклатуры` | **новая** — Товар / Материал / Услуга |

Добавленные ограничения: `CK_Номенклатура_Тип` (1/2/3), проверки цен ≥ 0,
проверка «минимальный остаток ≤ максимальный», `СрокГодности ≥ 0`,
`UNIQUE` на коде и Guid, `UNIQUE (ВидНоменклатурыId, Название)` у характеристик.

## Как читается номенклатура

```
КатегорияНоменклатуры      ГруппаНоменклатуры (дерево)      ЕдИзмерения
  «Товар»                     «Все номенклатуры»               м, кг, шт ...
  «Материал»                    ├─ Ткани
  «Услуга»                      ├─ Плитные материалы        ВидНоменклатуры
                                 ├─ Крепёж                   «ДСП», «фанера» ...
                                 └─ Фурнитура                     │
                                       │                          │ Характеристика
                                       │                          │ «Толщина», «Цвет кромки»
                                       ▼                          ▼
                                    Номенклатура  ──────────────►  ЗначениеХарактеристики
                                 (позиция: Код, Guid,
                                  БазоваяЕдИзмId, три цены,
                                  складские параметры)
```

Разделение понятий: **категория** отвечает на вопрос «что это» (товар,
материал, услуга), **вид номенклатуры** — «из чего это» (ДСП, фанера, ткань),
**характеристики** — свойства конкретного вида, **номенклатура** — позиция
каталога с ценами и складскими параметрами.

## Решения, принятые при переносе данных

| Поле | Значение | Почему |
|------|----------|--------|
| `Guid` | `4E000000-0000-0000-0000-<номер>` | детерминированный, чтобы повторный запуск скрипта не плодил дубли |
| `Код` | `НМ-00001` … `НМ-00352` | формируется из эталонного `Id` — в эталоне кода не было, а поле NOT NULL |
| `ТипId` | `1` (Товар) для всех 202 позиций | в эталоне `Номенклатура` — это то, что приходит и уходит по складу; принадлежность к материалу хранится в `ВидНоменклатуры`. Решение открытое — если нужна классификация по типу, поправьте одно значение |
| `ЦенаПродажная` | цена отпуска из эталона (`ценаОтпускаOснЕдЗм`) | это розничная цена отпуска, логично именно сюда; закупочная и оптовая остались пустыми |
| `Сокращение` единицы | равно названию | в эталоне сокращений не было |
| `Характеристика` | 5 записей для видов ДСП, фанера, саморезы, болт | видов «Ткань» в справочнике нет, поэтому 2 характеристики цвета/плотности не вставились |

Все 202 позиции получили `ВидНоменклатурыId` и `БазоваяЕдИзмId` — «висячих»
номенклатур нет.

## Почему без упаковки

Механизм второй единицы измерения из эталона не переносится: `колAliasЕдЗм` = 0
во всех 6773 строках движений, таблица коэффициентов перевода пуста. Одна
базовая единица на позицию — `ЕдИзмерения`.

## Связь с кадровой базой

`FOREIGN KEY` между базами невозможен, связь на `Guid`:
`Sklad_v1_HR.dbo.Сотрудник.Guid` ↔ `СотрудникGuid` в `Приход`, `Расход`, `Деньги`.

**Сверка битых ссылок** — результат должен быть пустым:

```sql
SELECT т.Таблица, т.Id, т.СотрудникGuid
FROM (
    SELECT N'Приход' AS Таблица, Id, СотрудникGuid FROM dbo.Приход WHERE СотрудникGuid IS NOT NULL
    UNION ALL SELECT N'Расход',  Id, СотрудникGuid FROM dbo.Расход  WHERE СотрудникGuid IS NOT NULL
    UNION ALL SELECT N'Деньги',  Id, СотрудникGuid FROM dbo.Деньги  WHERE СотрудникGuid IS NOT NULL) AS т
WHERE NOT EXISTS (SELECT 1 FROM [Sklad_v1_HR].dbo.Сотрудник] AS с WHERE с.[Guid] = т.СотрудникGuid);
```

## Про UETR

`UETR` — идентификатор **документа**, а не строки: в накладной несколько строк,
поэтому индекс по `UETR` намеренно **не уникальный**. Один `UETR` связывает
`Приход` + `Расход` + `Деньги`.

## Ключевые запросы

**Остаток по номенклатуре и складу:**

```sql
SELECT  н.[Код],
        н.[Название],
        ISNULL(п.Приход, 0) - ISNULL(р.Расход, 0) AS Остаток
FROM    dbo.Номенклатура AS н
LEFT JOIN (SELECT НоменклатураId, СкладId, SUM(Quantity) AS Приход
           FROM dbo.Приход GROUP BY НоменклатураId, СкладId) AS п
       ON п.НоменклатураId = н.[Id] AND п.СкладId = @СкладId
LEFT JOIN (SELECT НоменклатураId, СкладId, SUM(Quantity) AS Расход
           FROM dbo.Расход GROUP BY НоменклатураId, СкладId) AS р
       ON р.НоменклатураId = н.[Id] AND р.СкладId = @СкладId
WHERE   н.[Активен] = 1;
```

**Позиции ниже минимального остатка** — сигнал к закупке:

```sql
WITH остаток AS (
    SELECT ном.НоменклатураId, ном.СкладId,
           ISNULL(п.Приход, 0) - ISNULL(р.Расход, 0) AS Остаток
    FROM (SELECT НоменклатураId, СкладId, SUM(Quantity) AS Приход FROM dbo.Приход GROUP BY НоменклатураId, СкладId) п
    FULL JOIN (SELECT НоменклатураId, СкладId, SUM(Quantity) AS Расход FROM dbo.Расход GROUP BY НоменклатураId, СкладId) р
        ON р.НоменклатураId = п.НоменклатураId AND р.СкладId = п.СкладId)
SELECT н.[Код], н.[Название], о.Остаток, н.[МинимальныйОстаток]
FROM   остаток AS о
JOIN   dbo.Номенклатура AS н ON н.[Id] = о.НоменклатураId
WHERE  н.[МинимальныйОстаток] IS NOT NULL
  AND  о.Остаток < н.[МинимальныйОстаток];
```

```sql
       х.[Название] AS [Характеристика], з.[Значение]

LEFT JOIN dbo.ВидНоменклатуры AS вн ON вн.[Id] = н.[ВидНоменклатурыId]
LEFT JOIN dbo.ЗначениеХарактеристики AS з ON з.[НоменклатураId] = н.[Id]
LEFT JOIN dbo.Характеристика AS х ON х.[Id] = з.[ХарактеристикаId]
WHERE  н.[Код] = 'НМ-00002';
```
