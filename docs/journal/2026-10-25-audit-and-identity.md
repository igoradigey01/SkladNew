## Что сделано

### База `Sklad_v4.1.1`

- Создана как копия `Sklad-v4.1` через `BACKUP` / `RESTORE`
  (`db/sklad_v4_1_1/create-database.sql`), а не сборкой с нуля: схема, данные,
  индексы, триггеры и представления гарантированно совпадают с проверенной
  версией 4.1.
- Во все 19 бизнес-таблиц добавлены `СоздалId`, `ИзменилId`, `ДатаСоздания`,
  `ДатаИзменения` (`add-audit-columns.sql`). Скрипт идемпотентен: не дублирует
  колонки, приводит `datetime` к `datetime2`, заменяет default на
  `SYSUTCDATETIME()`.
- `verify-audit.sql` проверяет наличие колонок, тип, пустые `ДатаСоздания` и
  совпадение количества строк с `Sklad-v4.1`; при расхождении завершается
  ошибкой.

### Backend `backend/src/SkladApi`

- ASP.NET Core 8 Web API, пакеты EF Core 8.0.6, Identity, Dapper, Swagger.
- `SkladContext` — 11 EF-моделей (Группы 1 и 2) и автозаполнение аудита в
  `SaveChanges` / `SaveChangesAsync`. `IAuditable` реализован через базовый
  класс `AuditableEntity`.
- `HRContext` — Identity + существующая таблица `Сотрудник`
  (`ExcludeFromMigrations()`).
- `ApplicationUser` обязательно связан с `Сотрудник`:
  `СотрудникId int NOT NULL`, уникальный индекс, FK `ON DELETE NO ACTION`.
- Схема Identity применена миграцией `InitialIdentity`; идемпотентный SQL
  сохранён в `db/sklad_v1_hr/create-identity-tables.sql`.
- Строки подключения вынесены в User Secrets; `appsettings.json` в
  `.gitignore`. Без строк подключения приложение падает с понятным сообщением.

## Решения

| Вопрос | Решение | Почему |
|--------|---------|--------|
| Как создавать 4.1.1 | `BACKUP` / `RESTORE` из 4.1 | сохраняет данные и все объекты, исключает расхождения |
| Тип `СоздалId` / `ИзменилId` | `nvarchar(450)` | совпадает с `AspNetUsers.Id`, не нужно приведение |
| Даты | `datetime2`, UTC (`SYSUTCDATETIME`, `DateTime.UtcNow`) | единая шкала времени, нет зависимости от часового пояса сервера |
| Nullability `ДатаИзменения` | сохраняется как была | у `ЗначениеХарактеристики` она `NOT NULL` ещё с v4 |
| Группа 3 | колонки есть, EF-моделей нет | код их не трогает, колонки остаются `NULL` |
| `Сотрудник` | `ExcludeFromMigrations()` | таблица создана SQL-скриптами, EF не должен её пересоздавать |
| `SkladContext` | без миграций | схема управляется SQL-скриптами, EF только читает/пишет |

## Ограничения и что дальше

- Бизнес-эндпоинтов пока нет: готов только каркас (DI, Identity, аудит,
  Swagger). Следующий шаг — CRUD для транзакционных таблиц и Dapper-запросы.
- Нет сидирования администратора и ролей: первую учётку нужно заводить
  вручную, предварительно создав `Сотрудник`.
- `СоздалId` / `ИзменилId` — логическая ссылка на `AspNetUsers`; FK между
  базами невозможен, сверка только запросом.
- Аудит хранит «кто и когда последний раз», а не полную историю изменений.
  Если понадобится история сумм и остатков — отдельная таблица журнала.
- Frontend (Angular) не начат.
