# Схема БД `Sklad_v4.1.1` — версия 4.1 + аудит

`Sklad_v4.1.1` — это **копия** [`Sklad-v4.1`](../sklad_v4_1/database-schema.md)
со всеми данными, индексами, триггерами и представлениями, в которую добавлены
четыре колонки аудита во все 19 бизнес-таблиц.

База создаётся не с нуля, а через `BACKUP` / `RESTORE`: так гарантируется, что
схема и данные совпадают с проверенной версией 4.1, а не собираются заново.

## Колонки аудита

Во всех 19 бизнес-таблицах:

| Колонка | Тип | Nullability | Назначение |
|---------|-----|-------------|------------|
| `СоздалId` | `nvarchar(450)` | `NULL` | `AspNetUsers.Id` пользователя, создавшего запись |
| `ИзменилId` | `nvarchar(450)` | `NULL` | `AspNetUsers.Id` пользователя, изменившего запись |
| `ДатаСоздания` | `datetime2` | `NOT NULL`, DEFAULT `SYSUTCDATETIME()` | момент создания, UTC |
| `ДатаИзменения` | `datetime2` | `NULL` | момент последнего изменения, UTC |

`nvarchar(450)` выбран под ключ ASP.NET Identity (`AspNetUsers.Id` —
`nvarchar(450)`), чтобы значение можно было сравнить без приведения типов.

Даты хранятся в UTC: `SYSUTCDATETIME()` в БД и `DateTime.UtcNow` в приложении.
`ДатаИзменения` у `ЗначениеХарактеристики` была в v4 и осталась `NOT NULL` —
скрипт сохраняет существующую nullability, а не навязывает свою.

## Где аудит заполняется кодом

Колонки есть у всех таблиц, но EF-модели и `IAuditable` реализованы только для
критичных таблиц (задача 02). Остальные колонки остаются `NULL` — это осознанное
решение, а не недоделка.

| Группа | Таблицы | Аудит в коде |
|--------|---------|--------------|
| 1. Транзакционные | `Приход`, `Расход`, `Деньги`, `НакладнаяРасход`, `Сделка`, `Расхождение`, `Ревизия` | да |
| 2. Основные справочники | `Номенклатура`, `Клиент`, `Поставщик`, `Склад` | да |
| 3. Вспомогательные | `ВидНоменклатуры`, `ГруппаНоменклатуры`, `ЕдИзмерения`, `КатегорияНоменклатуры`, `СписокЗначений`, `ТипЗначения`, `Характеристика`, `ЗначениеХарактеристики` | нет, колонки остаются `NULL` |

Модели Группы 3 в `SkladContext` не описаны: EF их не видит и не трогает.

## Файлы

| Файл | Что делает |
|------|------------|
| `create-database.sql` | `BACKUP` базы `Sklad-v4.1` и `RESTORE` под именем `Sklad_v4.1.1` |
| `add-audit-columns.sql` | Идемпотентно добавляет 4 колонки аудита во все 19 таблиц |
| `verify-audit.sql` | Проверяет наличие колонок, тип `datetime2`, отсутствие пустых `ДатаСоздания` и совпадение количества строк с `Sklad-v4.1` |

## Развёртывание

```bash
cd SkladNew/db/sklad_v4_1_1

# 1. Копия данных и схемы Sklad-v4.1
sqlcmd -S localhost -U sa -P '<пароль>' -C -f 65001 -b -i create-database.sql

# 2. Колонки аудита
sqlcmd -S localhost -U sa -P '<пароль>' -C -f 65001 -b -i add-audit-columns.sql

# 3. Проверка (при расхождении завершится ошибкой)
sqlcmd -S localhost -U sa -P '<пароль>' -C -f 65001 -b -i verify-audit.sql
```

`create-database.sql` удаляет существующую `Sklad_v4.1.1`, делает
`COPY_ONLY`-бэкап источника и восстанавливает копию с переносом файлов
`Sklad-v4.1.mdf` / `Sklad-v4.1_log.ldf` в `Sklad_v4.1.1.mdf` /
`Sklad_v4.1.1_log.ldf`. Источник при этом не меняется.

`add-audit-columns.sql` можно запускать повторно: существующие колонки не
дублируются, `datetime` приводится к `datetime2`, default-ограничение
заменяется на `SYSUTCDATETIME()`.

## Проверено

- 19 бизнес-таблиц, во всех есть 4 колонки; типы — `datetime2`.
- `ДатаСоздания` заполнена у всех существующих строк (default сработал).
- Количество строк в каждой таблице совпадает с `Sklad-v4.1`.
- Smoke-тест EF: `СоздалId`, `ИзменилId`, `ДатаСоздания`, `ДатаИзменения`
  заполняются при `INSERT` и `UPDATE`.

## Что помнить

1. **Связи с `AspNetUsers` нет.** Пользователи живут в `Sklad_v1_HR`, а FK
   между базами в SQL Server невозможен. `СоздалId` / `ИзменилId` — логическая
   ссылка, сверяется запросом.
2. **Имя базы с точками.** В T-SQL — `USE [Sklad_v4.1.1]`, в строке
   подключения — `Database=Sklad_v4.1.1`.
3. **Аудит — не история.** Колонки хранят только «кто и когда последний раз».
   Полная история изменений сумм и остатков — отдельная задача (журнал
   операций), если она понадобится.
