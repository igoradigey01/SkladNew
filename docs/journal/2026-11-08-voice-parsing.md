# 2026-11-08 — разбор накладной голосом

## Что появилось

| Компонент | Назначение |
|---|---|
| `Controllers/InvoiceController.cs` | `POST /api/invoice/parse-voice`: текст → позиции |
| `Services/OllamaSettings.cs` | адрес и модель Ollama (`http://10.42.0.100:11434`, `qwen2.5:7b-instruct`) |
| `Services/FuzzyMatcher.cs` | Левенштейн + проверка чисел |
| `Repository/НоменклатураRepository.cs` | активная номенклатура из `dbo.Номенклатура` |
| `Controllers/NomenclatureController.cs` | `GET /api/nomenclature?q=&limit=` |
| `SkladApi.Tests` | 10 тестов: FuzzyMatcher и InvoiceController с fake HttpClient |

## Решения

- `gemma2b-invoice` не установлена — используем `qwen2.5:7b-instruct`;
- JSON-схема ответа (`{"items":[…]}`) вместо `format: "json"`: иначе модель возвращала
  одну позицию;
- few-shot примеры в промте: без них модель принимала размер за количество;
- порог сопоставления 75%, плюс отбрасывание кандидатов с несовпадающими числами;
- 503 при недоступной БД вместо стектрейса.

## Выбор модели (2026-11-08, вечер)

Сравнение на живых фразах: `qwen2.5:7b-instruct` против `qwen2.5:14b-instruct`
(обе уже на ks34, скачивать нечего).

| Фраза | 7B | 14B |
|---|---|---|
| «два мешка шпатлевки и полтора килограмма гвоздей» | raw_name «два мешка шпатлевки», unit пусто | «шпатлевки» × 2 мешка, «гвоздей» × 1.5 килограмма |
| «шайба 10 100 штук и гвозди 2,5х50 три кило» | unit «кilo» (латиница) | «кило» |
| «шайба цинк 10, 100 штук…» | верно | верно |

Латентность (прогретая модель): 7B — 3–9 с, 14B — 3–7 с. Качество нормализации
у 14B выше, поэтому по умолчанию выбрана она (`Ollama:Model`).

`gemma4:e4b` и `gemma4:e2b` на сервере **не установлены** (есть только `gemma4:26b`),
поэтому сравнение с ними не делалось.

## Бенчмарк трёх моделей (18 фраз)

Скрипт: `scripts/bench-voice.py` (запуск `python3 scripts/bench-voice.py --json out.json`).
18 фраз, 27 ожидаемых позиций: размеры, числа словами, самокоррекция, десятичная запятая,
позиции без количества, отсутствующие в БД товары.

| Модель | Верно | Лишних | Ошибок | Среднее | Макс |
|---|---|---|---|---|---|
| `qwen2.5:7b-instruct` | 24/27 | 3 | 0 | 1.42 c | 8.83 c |
| `qwen2.5:14b-instruct` | **27/27** | 0 | 0 | 4.14 c | 13.72 c |
| `gemma4:e2b` | 26/27 | 2 | 0 | 1.19 c | 10.84 c |

Дефекты:

- **gemma4:e2b** — «гайка кошка 10, 50 штук» разложила в две строки
  («гайка кошка» × 10 и × 50); «2,5 кг» превратила в 2. Первый прогон также
  копировала пример из промта («шайба цинк 10, 100 штук»), после замены примера
  на нейтральный («краска белая») дефект ушёл, но дублирование осталось.
- **qwen2.5:7b** — unit «кilo» латиницей, «2,5» → 2, теряет «шт» у «правило».
- **qwen2.5:14b** — на этом наборе ошибок нет.

Решение: по умолчанию остаётся `qwen2.5:14b-instruct`. `gemma4:e2b` в 3.5 раза
быстрее, но дублирование строки и обрезанное количество — недопустимы в накладной.
Для gemma в контроллер добавлен `think: false` (иначе 3.4 с вместо 0.4 с на ответ).

## Промт для gemma4:e2b: четыре варианта

| Вариант | Верно | Лишних | Среднее |
|---|---|---|---|
| A. наш промт + JSON-схема | **26/27** | 1 | 0.88 c |
| B. короткий промт («робот-кладовщик») + схема | 24/27 | 3 | 0.65 c |
| C. короткий промт без схемы | 0/27 | 24 | 0.33 c |
| D. наш промт + правила про дроби и «одна позиция = одна строка» | 24/27 | 0 | 0.36 c |

Выводы:

- JSON-схема в запросе важнее текста промта: без неё gemma вернула `quantity: "5 кг"`
  строкой и разбор упал;
- короткий промт хуже нашего на 2 позиции и даёт больше лишних строк;
- вариант D убрал дублирование, но начал **обрезать** многострочные накладные:
  из «саморезы … и саморезы …» вернул только первую позицию;
- лучший для gemma — текущий промт (A); для продакшена всё равно 14B (27/27).

## gemma4:e4b и правило про единицы измерения

Добавлено в промт: «Слова «кг», «мешок», «штук», «метр» — это unit, в raw_name их не включай».
Именно на этом ломался e4b («два мешка шпатлевки» → `raw_name: "мешки шпатлевки"`, unit пусто).

Итог на 18 фразах (27 позиций):

| Модель | Верно | Лишних | Среднее | Макс |
|---|---|---|---|---|
| `qwen2.5:7b-instruct` | 22/27 | 5 | 1.29 c | 8.72 c |
| `qwen2.5:14b-instruct` | 27/27 | 0 | 4.10 c | 13.53 c |
| `gemma4:e2b` | 27/27 | 0 | 1.14 c | 10.27 c |
| `gemma4:e4b` | **27/27** | 0 | 1.16 c | 10.63 c |

Проверка на held-out (6 фраз, 8 позиций, в бенчмарк не входили):
`gemma4:e4b` — 8/8, `gemma4:e2b` — 8/8, `qwen2.5:14b-instruct` — 8/8.

Решение: по умолчанию `gemma4:e4b` (первый запрос после простоя — до 12 с,
дальше 0.6–1.3 с), `qwen2.5:14b-instruct` остаётся запасной через `Ollama:Model`.
